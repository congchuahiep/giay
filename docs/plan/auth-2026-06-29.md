## 1. Tổng quan mục tiêu

Xây dựng luồng đăng nhập hoàn chỉnh cho Tauri Desktop App, với JWT token được lưu trong Keyring của hệ điều hành (Windows Credential Manager / macOS Keychain / Linux Secret Service).

### Luồng người dùng

```
Mở app → Kiểm tra Keyring có token không?
  ├── Có token → Gọi /auth/me để xác thực
  │     ├── 200 → Vào thẳng trang chính (/)
  │     └── 401 → Refresh token
  │           ├── 200 → Lưu token mới → retry /auth/me → vào trang chính
  │           └── 401 → Xóa token → hiện trang /login
  └── Không có token → Hiện trang /login

Trang /login → Nhập email + password → POST /auth/login
  ├── 200 → Lưu token vào Keyring → navigate("/")
  └── 401 → Hiện lỗi "Sai email hoặc mật khẩu"

Trang / (protected) → beforeLoad kiểm tra auth
  ├── Đã auth → Render trang chính
  └── Chưa auth → redirect("/login")
```

**4 Tauri Commands:**

| Command             | JS gọi                                                 | Output                              | Mô tả             |
| ------------------- | ------------------------------------------------------ | ----------------------------------- | ----------------- |
| `save_tokens`       | `invoke("save_tokens", { accessToken, refreshToken })` | `Result<(), AuthError>`             | Lưu vào Keyring   |
| `get_access_token`  | `invoke("get_access_token")`                           | `Result<Option<String>, AuthError>` | Đọc access token  |
| `get_refresh_token` | `invoke("get_refresh_token")`                          | `Result<Option<String>, AuthError>` | Đọc refresh token |
| `clear_tokens`      | `invoke("clear_tokens")`                               | `Result<(), AuthError>`             | Xóa cả 2 token    |

**Chi tiết kỹ thuật:**

- Service name: `env!("CARGO_PKG_NAME")` — compile-time macro, tự lấy từ `Cargo.toml`
- Dùng `set_password` / `get_password` (JWT là UTF-8 string, không cần `set_secret`)
- `keyring::Error::NoEntry` → trả về `Ok(None)` (không phải lỗi, chỉ là chưa có token)
- `AuthError` có 2 variant: `KeyringAccess` (HĐH không hỗ trợ keyring), `Keyring(String)` (lỗi khác)
- `AuthError` derive `serde::Serialize` → frontend nhận structured error `{"type": "KeyringAccess", "message": null}`

### Bước 3: Utils — classifyApiError ✅ Đã hoàn thành

**Files đã tạo:**

- `src/utils/classify-api-error.ts`

**Hàm chính:** `classifyApiError(error: unknown): AppError`

Convert `AxiosError` (thô) → appropriate `AppError` subclass. Là **classifier thuần túy** — chỉ phân loại lỗi, không quyết định xóa token hay redirect.

**Logic phân loại:**

- Không phải AxiosError → `AppError`
- Không có response → `TimeoutError` hoặc `NetworkError`
- 400 + field errors (trong `details`) → `ValidationError`
- 400 + `detail` string → `AppError`
- **401 → luôn `AuthError(message, apiCode)`** (không cần `handleAuthError` — refresh interceptor ở Step 6 quyết định có xóa token không)
- 403 → `ForbiddenError`
- 404 → `NotFoundError`
- 5xx → `ServerError`

**Tách biệt trách nhiệm:**

```
classifyApiError       → "Đây là lỗi loại gì?" (phân loại)
Refresh Interceptor    → "Có nên xóa token không?" (quyết định, Step 6)
Component              → "Redirect login hay hiện lỗi form?" (hành động)
```

**Cấu trúc error response từ backend:**

```json
{
  "code": "ERROR_CODE",
  "message": "Error message",
  "details": { "field1": "Invalid value", ... }
}
```

```typescript
type EndpointFn<E> = (endpoints: E) => string;

interface ApiClient<E> {
  get<T>(fn: EndpointFn<E>, config?): Promise<AxiosResponse<T>>;
  post<T>(fn: EndpointFn<E>, data?, config?): Promise<AxiosResponse<T>>;
```

**tauri-token-provider.ts — Keyring + in-memory cache:**

Lý do cần cache: Keyring đọc qua IPC (5-20ms), localStorage đọc ~0.01ms. Nếu mỗi API call đều đọc Keyring → overhead đáng kể. Cache giải quyết bằng cách chỉ đọc Keyring 1 lần (khi app khởi động), sau đó đọc từ RAM.

```typescript
class TauriTokenProvider implements TokenProvider {
  private cachedAccess: string | null = null;
  private cachedRefresh: string | null = null;
  private initialized = false;

  async getAccessToken(): Promise<string | null> {
    if (!this.initialized) {
      this.cachedAccess = await tauriAuthCommands.getAccessToken();
      this.initialized = true;
    }
    return this.cachedAccess;
  }

  async saveTokens(access: string, refresh: string): Promise<void> {
    await tauriAuthCommands.saveTokens(access, refresh);
    this.cachedAccess = access;
    this.cachedRefresh = refresh;
    this.initialized = true;
  }

  async clearTokens(): Promise<void> {
    await tauriAuthCommands.clearTokens();
    this.cachedAccess = null;
    this.cachedRefresh = null;
  }
}
```

**Hiệu năng:**

```
Lần đầu (app khởi động):
  getAccessToken() → invoke("get_access_token") → Keyring → 5-20ms → cache

Mọi API call sau đó:
  getAccessToken() → đọc từ cache → ~0ms → chèn vào header

Login/Logout/Refresh:
  saveTokens()/clearTokens() → ghi Keyring + cập nhật cache
```

### Bước 6: Auth Feature — Lib (Auth Interceptors)

**Files cần tạo:**

- `src/features/auth/lib/auth-interceptors.ts`

**Mục đích:** Setup interceptors trên `authAxios` — đây là logic auth, không phải config.

**3 interceptors (thứ tự QUAN TRỌNG):**

```
Interceptor                    Thứ tự thêm    Chạy khi?           Vai trò
──────────────────────────────────────────────────────────────────────────
1. Request: thêm token         1             Trước khi gửi       Chèn Authorization header
2. Response: 401 → refresh     2             Nhận 401            Refresh token → retry request
3. Response: error formatting  3             Nhận error khác     Convert AxiosError → AppError
```

Axios chạy response interceptors theo FIFO (thêm trước chạy trước). Thứ tự trên đảm bảo:

- 401 refresh chạy TRƯỚC error formatting → nhận original AxiosError (có `error.config` để retry)
- Nếu refresh thành công → trả response 200 → error formatting bị bỏ qua
- Nếu refresh thất bại → throw error → error formatting xử lý → convert thành AppError

**Request interceptor:**

```typescript
authAxios.interceptors.request.use(async (config) => {
  const token = await tokenProvider.getAccessToken(); // Đọc từ cache (nhanh)
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});
```

**Response interceptor (401 → refresh):**

```typescript
let refreshPromise: Promise<string> | null = null;

authAxios.interceptors.response.use(
  (response) => response,
  async (error) => {
    const originalRequest = error.config;

    // Chỉ xử lý 401 và chưa retry
    if (error.response?.status !== 401 || originalRequest._retried) {
      throw error; // Chuyển cho error formatting interceptor
    }

    // Singleton refresh — tránh gọi refresh nhiều lần khi có nhiều request cùng 401
    if (!refreshPromise) {
      refreshPromise = doRefresh().finally(() => {
        refreshPromise = null;
      });
    }

    try {
      const newToken = await refreshPromise;
      originalRequest._retried = true;
      originalRequest.headers.Authorization = `Bearer ${newToken}`;
      return authAxios(originalRequest); // Retry request gốc
    } catch {
      // Refresh thất bại → clear tokens → error formatting sẽ xử lý
      await tokenProvider.clearTokens();
      throw error;
    }
  },
);

async function doRefresh(): Promise<string> {
  const refreshToken = await tokenProvider.getRefreshToken();
  if (!refreshToken) throw new Error("No refresh token");

  // Dùng publicApi (không có auth interceptor → tránh infinite loop)
  const response = await publicApi.post<TokenResponse>(
    (ep) => ep.auth.refresh,
    {
      refresh_token: refreshToken,
    },
  );

  await tokenProvider.saveTokens(
    response.data.access_token,
    response.data.refresh_token,
  );
  return response.data.access_token;
}
```

**Response interceptor (error formatting):**

```typescript
authAxios.interceptors.response.use(
  (response) => response,
  (error) => {
    throw handleAxiosError(error);
  },
);
```

**useLogin (mutation):**

```typescript
export default function useLogin(
  options?: UseMutationOptions<void, AppError, LoginRequest>,
) {
  return useMutation({
    ...options,
    mutationFn: async (data) => {
      // 1. Gọi API login (qua publicApi — không cần auth)
      const response = await publicApi.post<TokenResponse>(
        (ep) => ep.auth.login,
        data,
      );
      // 2. Lưu token vào Keyring + cache
      await tokenProvider.saveTokens(
        response.data.access_token,
        response.data.refresh_token,
      );
      // 3. Decode JWT để lấy user info
      const user = decodeJwt(response.data.access_token);
      // 4. Cập nhật store
      useAuthStore.getState().setUser(user);
      useAuthStore.getState().setAuthenticated(true);
    },
  });
}
```

**useLogout (mutation):**

```typescript
export default function useLogout(
  options?: UseMutationOptions<void, AppError>,
) {
  const queryClient = useQueryClient();
  return useMutation({
    ...options,
    mutationFn: async () => {
      const refreshToken = await tokenProvider.getRefreshToken();
      if (refreshToken) {
        await publicApi.post((ep) => ep.auth.logout, {
          refresh_token: refreshToken,
        });
      }
      await tokenProvider.clearTokens();
      useAuthStore.getState().reset();
      queryClient.clear(); // Xóa toàn bộ cache — tránh hiển thị data user cũ
    },
  });
}
```

```typescript
      return userProfileFromDto(response.data);
    },
    enabled: useAuthStore.getState().isAuthenticated,
    staleTime: 5 * 60 * 1000,
  });
}
```

## 7. Ghi chú quan trọng

1. **Keyring trên Linux**: Cần `gnome-keyring-daemon` hoặc `kwalletd` đang chạy. Nếu không có, keyring sẽ fail với `AuthError::KeyringAccess`.
2. **macOS Keychain dialog**: Lần đầu ghi Keychain, macOS hiện dialog xin quyền. Cần sign app với Developer ID khi build production.
3. **`defaultPreloadStaleTime: 0`**: Bắt buộc set để TanStack Query quản lý cache, Router không can thiệp.
4. **Axios interceptor singleton refresh**: Tránh gọi refresh token nhiều lần khi có nhiều request cùng nhận 401 — dùng `refreshPromise` singleton.
5. **`queryClient.clear()` khi logout**: Xóa toàn bộ cache để tránh hiển thị data của user cũ.
6. **Cập nhật `routeTree.gen.ts`**: Sau khi thêm file routes mới, file này tự cập nhật. KHÔNG sửa tay.
7. **Barrel export**: External code CHỈ import từ `@/features/auth`, KHÔNG import sâu hơn (`@/features/auth/lib/...`). Có thể dùng ESLint rule `import/no-internal-modules` để enforce.
8. **Interceptor ordering**: 401-refresh phải chạy TRƯỚC error formatting. `configs/api.ts` chỉ thêm error formatting cho `publicAxios`. `authAxios` nhận ALL interceptors từ `features/auth/lib/auth-interceptors.ts` (đúng thứ tự).
9. **Token cache**: `TauriTokenProvider` cache token trong RAM. Keyring chỉ đọc 1 lần khi app khởi động. Mọi API call sau đó đọc từ cache (~0ms).
10. **2 axios instances**: `publicApi` (login, register, refresh, logout — không auth header) + `authApi` (mọi API cần auth — tự chèn token, tự refresh 401). Tách tránh infinite loop khi refresh.
