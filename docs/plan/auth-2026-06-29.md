## 1. Tổng quan mục tiêu

Xây dựng luồng đăng nhập hoàn chỉnh cho Tauri Desktop App, với JWT token được lưu trong Keyring của hệ điều hành (Windows Credential Manager / macOS Keychain / Linux Secret Service).

### Luồng người dùng

```
Mở app → Kiểm tra Keyring có token không?
  ├── Có token → Gọi /auth/me để xác thực
  │     ├── 200 → Vào thẳng trang chính (/)
  │     └── 401 → Refresh token
  │           ├── 200 → Lưu token mới → retry /auth/me → vào trang chính
  │           └── 401 → Xóa token → hiện trang /login
  └── Không có token → Hiện trang /login

Trang /login → Nhập email + password → POST /auth/login
  ├── 200 → Lưu token vào Keyring → navigate("/")
  └── 401 → Hiện lỗi "Sai email hoặc mật khẩu"

Trang / (protected) → beforeLoad kiểm tra auth
  ├── Đã auth → Render trang chính
  └── Chưa auth → redirect("/login")
```

## 3. Các bước triển khai

### Bước 1: Rust — Tauri Commands

**Files cần sửa/tạo:**

- `src-tauri/src/auth/command.rs` — Viết 4 command
- `src-tauri/src/auth/mod.rs` — Re-export (đã có, cần cập nhật)
- `src-tauri/src/lib.rs` — Đăng ký commands trong `generate_handler!`

**4 Tauri Commands cần viết:**

| Command             | Input                                | Output                           | Mô tả             |
| ------------------- | ------------------------------------ | -------------------------------- | ----------------- |
| `save_tokens`       | access_token, refresh_token (String) | `Result<(), String>`             | Lưu vào Keyring   |
| `get_access_token`  | —                                    | `Result<Option<String>, String>` | Đọc access token  |
| `get_refresh_token` | —                                    | `Result<Option<String>, String>` | Đọc refresh token |
| `clear_tokens`      | —                                    | `Result<(), String>`             | Xóa cả 2 token    |

**Chi tiết kỹ thuật Rust:**

- Service name: `"giay"` (tên app, hardcode), lấy từ `Cargo.toml`
- Entry: `keyring::Entry::new("giay", "access_token")` / `keyring::Entry::new("giay", "refresh_token")`
- set_password để ghi, get_password để đọc, delete_credential để xóa
- Xử lý `keyring::Error::NoEntry` — trả về `Ok(None)`, không phải lỗi

**Đăng ký trong lib.rs:**

```rust
.invoke_handler(tauri::generate_handler![
    auth::command::save_tokens,
    auth::command::get_access_token,
    auth::command::get_refresh_token,
    auth::command::clear_tokens,
])/
```

### Bước 2: Shared — Axios Instance + Interceptors

**Files cần tạo:**

- `src/shared/lib/api.ts`

**Axios instance:**

- Base URL: `http://localhost:3000/api` (cấu hình qua env variable)
- `Content-Type: application/json` mặc định

**Request Interceptor:**

1. Gọi `invoke("get_access_token")` để lấy token từ Keyring
2. Nếu có, set `Authorization: Bearer <token>` header

**Response Interceptor:**

1. Bắt response có status 401
2. Tránh refresh trùng lặp: singleton promise `refreshPromise`
3. Gọi `POST /api/auth/refresh-token` với refresh_token từ Keyring
4. Nếu refresh OK (200): lưu token mới vào Keyring → retry request gốc với token mới
5. Nếu refresh fail (401): xóa token trong Keyring → chuyển đến `/login`

### Bước 3: Shared — Tauri Commands Wrapper

**Files cần tạo:**

- `src/shared/lib/tauri-commands.ts`

**Mục đích:** Ép kiểu kết quả từ `invoke()` (trả về `unknown`) sang type cụ thể.

```typescript
// Giao diện clean cho frontend gọi
export const tauriAuth = {
  saveTokens: (accessToken: string, refreshToken: string) =>
    invoke("save_tokens", { accessToken, refreshToken }),
  getAccessToken: () => invoke<string | null>("get_access_token"),
  getRefreshToken: () => invoke<string | null>("get_refresh_token"),
  clearTokens: () => invoke("clear_tokens"),
};
```

### Bước 4: Auth Feature — API Layer

**Files cần tạo:**

- `src/features/auth/types.ts`
- `src/features/auth/api/auth-api.ts`

**Types:**

```typescript
interface LoginRequest {
  email: string;
  password: string;
}
interface TokenResponse {
  access_token: string;
  refresh_token: string;
}
interface User {
  id: string;
  email: string;
  name?: string;
}
interface AuthState {
  isAuthenticated: boolean;
  user: User | null;
  login: (email: string, password: string) => Promise<void>;
  logout: () => Promise<void>;
}
```

**auth-api.ts:**

- `login(body: LoginRequest): Promise<TokenResponse>` — POST /auth/login
- `me(): Promise<User>` — GET /auth/me
- `refreshToken(refreshToken: string): Promise<TokenResponse>` — POST /auth/refresh-token
- `logout(refreshToken: string): Promise<void>` — POST /auth/logout

Mỗi hàm chỉ gọi axios instance, không chứa logic state.

### Bước 5: Auth Feature — Zustand Store

**Files cần tạo:**

- `src/features/auth/stores/auth-store.ts`

**Tại sao cần Zustand store?**

- Keyring là persistent (lưu đĩa, chậm vì gọi qua Rust)
- Store là in-memory (nhanh, component subscribe được)
- Keyring chỉ gọi 2 lúc: khởi động (đọc) và login/logout (ghi)

**Store state:**

```typescript
{
  isAuthenticated: boolean; // false mặc định
  user: User | null; // null mặc định
}
```

**Store actions:**

- `setUser(user: User)` — Set sau khi login hoặc verify token
- `setAuthenticated(value: boolean)` — Set trạng thái auth
- `reset()` — Reset về mặc định (dùng khi logout)

### Bước 6: Auth Feature — Hooks

**Files cần tạo:**

- `src/features/auth/hooks/use-login.ts`
- `src/features/auth/hooks/use-logout.ts`
- `src/features/auth/hooks/use-current-user.ts`

**useLogin (mutation):**

- `mutationFn`: Gọi `authApi.login()` → lưu token qua `tauriAuth.saveTokens()` → `authStore.setUser()` → `authStore.setAuthenticated(true)`
- `onSuccess`: `router.navigate({ to: redirectUrl })`

**useLogout (mutation):**

- `mutationFn`: Đọc refresh_token → gọi `authApi.logout()` → gọi `tauriAuth.clearTokens()` → `authStore.reset()` → `queryClient.clear()`
- `onSuccess`: `router.navigate({ to: '/login' })`

**useCurrentUser (query):**

- `queryKey: ['auth', 'me']`
- `queryFn`: `authApi.me()`
- `enabled: !!store.isAuthenticated`
- `staleTime: 5 * 60 * 1000` (cache 5 phút)

**Files cần tạo/sửa:**

**query-client.ts:**

```typescript
export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 60 * 1000, // 1 phút mới stale
      retry: 1, // Retry 1 lần khi lỗi
    },
  },
});
```

**router.ts:**

```typescript
export const router = createRouter({
  routeTree,
  context: {
    auth: useAuthStore.getState(), // Zustand store
    queryClient, // TanStack Query client
  },
  defaultPreloadStaleTime: 0, // Để Query quản lý cache, Router không cache
});
```

**providers.tsx:**


- Validate search params: `redirect?: string`

- beforeLoad: Kiểm tra `context.auth.isAuthenticated`

- Nếu cả 2 thất bại: `redirect({ to: '/login', search: { redirect: location.href } })`
- Component: Chỉ render `<Outlet />` (sau này thêm sidebar/header)

**\_authenticated/index.tsx — Trang Home:**

- Hiển thị thông tin user từ `useCurrentUser()`

## 6. Kiểm thử thủ công

Sau khi hoàn thành các bước, kiểm tra theo checklist:

- [ ] `bun tauri dev` — App mở không lỗi
- [ ] Truy cập `/` khi chưa login → redirect `/login`
- [ ] Nhập email/password sai → hiện lỗi
- [ ] Nhập email/password đúng → redirect `/` → hiện user info
- [ ] Đóng app, mở lại → vẫn vào thẳng `/` (không cần login lại)
- [ ] Click Đăng xuất → redirect `/login`
- [ ] Mở lại app → vào `/` → bắt login lại (token đã bị xóa)
- [ ] Đợi access token hết hạn (15p) → API call tự refresh → vẫn hoạt động

## 7. Ghi chú quan trọng

1. **Keyring trên Linux**: Cần `gnome-keyring-daemon` hoặc `kwalletd` đang chạy. Nếu không có, keyring sẽ fail.
2. **macOS Keychain dialog**: Lần đầu ghi Keychain, macOS hiện dialog xin quyền. Cần sign app với Developer ID khi build production.
3. **`defaultPreloadStaleTime: 0`**: Bắt buộc set để TanStack Query quản lý cache, Router không can thiệp.
4. **Axios interceptor singleton refresh**: Tránh gọi refresh token nhiều lần khi có nhiều request cùng nhận 401.
5. **`queryClient.clear()` khi logout**: Xóa toàn bộ cache để tránh hiển thị data của user cũ.
6. **Cập nhật `routeTree.gen.ts`**: Sau khi thêm file routes mới, file này tự cập nhật. KHÔNG sửa tay.
